# postgresx 标准

**crate**：`postgresx` v0.1.0 · 依赖：`tokio-postgres` / `deadpool-postgres`、`tokio`、`rustls` 生态、`serde` / `serde_json`、`sha2`、`thiserror`、`toml`、`tracing`

## 1. 定位

postgresx 提供 PostgreSQL 适配原语：连接池、参数化 SQL、事务、schema 迁移、rustls TLS
与带预算的重试。零内部依赖，只依赖 crates.io 公开包。不提供 ORM、查询构建器、领域模型
或调度编排。

## 2. 字段治理

- 环境变量前缀统一为 `FOUNDATIONX_POSTGRESX_`；字段、环境变量与 TOML 键一一对应，
  公开 `ENV_*` / `DEFAULT_*` 常量。
- 配置四入口等价：`from_env()` / `from_toml()` / `from_url()` / `builder()`；
  `FOUNDATIONX_POSTGRESX_URL` 作为其余环境变量的基底。
- TOML 严格解析：未知键（包括误写的 `password`）直接报错，不静默忽略。
- 密码不是公开字段：只能经环境变量 / URL / builder 注入；`Debug` 对 `password` 输出 `***`；
  密码永不进入日志。

## 3. 安全约定

- 所有查询 API 只接受 `$N` 占位符 + `ToSql` 参数，不提供字符串拼接 SQL 的公开入口。
- 非 loopback 主机在 `validate()` 阶段强制 `sslmode=require`（`disable` / `prefer` 仅限本机）。
- rustls 始终校验服务端证书，无 insecure 旁路；mTLS 客户端证书与私钥必须成对提供。
- `acquire_timeout` / `operation_timeout` 覆盖所有阻塞点；`operation_timeout` 同时下发
  `statement_timeout`。超时或任务取消时连接脱池，不归还状态未知的连接。

## 4. 迁移与失败处理

- 每条迁移记录 SHA-256 checksum；已应用版本的 SQL 被修改即报 `ChecksumMismatch` 并 fail-closed。
- 每条迁移在独立事务内取 `pg_advisory_xact_lock(MIGRATION_LOCK_KEY1, MIGRATION_LOCK_KEY2)`，
  多实例并发启动串行执行，commit/rollback 自动释放。
- `verify()` 只校验、不执行 DDL；`ensure_boot_ok()` 对 mismatch / 未知版本 fail-closed；
  执行 pending 必须显式 `apply()`。
- 事务块内禁用语句（`CREATE INDEX CONCURRENTLY` / `VACUUM` 等）保守拒绝为
  `PostgresError::Unsupported`。
- 错误统一经 SQLSTATE 语义分类（`ErrorKind`）；可重试判定走 `PostgresError::is_retryable()`，
  重试经 `PgRetryConfig`（指数退避 + 抖动 + 总预算 deadline）。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

集成测试全部离线运行：不依赖真实 PostgreSQL 实例，失败路径统一使用 `127.0.0.1:1`
（必然拒绝连接）。至少覆盖配置四入口与严格 TOML 解析、密码脱敏、SSL 模式与主机校验、
SQLSTATE 分类、重试预算与退避、checksum 与迁移校验纯函数、公开 API 面。
